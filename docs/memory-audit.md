# 内存与轻量化审查

## 测量结论

本机为 MacBook Air M5 13 英寸、macOS 27。开始审查时，已经使用过的旧版在设置打开状态约为 **47.2 MiB physical footprint**，关闭设置后约 **48.3 MiB**。这是已有进程的单次记录，不应与冷启动测量混作严格的前后百分比。

下表为相同本机、原有偏好、同一采样工具下的三轮独立冷启动。启动后等待 0.3 秒，每 0.2 秒采样；空闲和设置各 25 个样本，演示动画 40 个样本。每个数值是三轮采样末值的中位数；设置场景始终开窗，并合计主进程与直接设置子进程。

| 场景 | 原版 | 最终优化版 |
| --- | ---: | ---: |
| 冷启动空闲 | 11.69 MiB | 11.38 MiB |
| 设置打开 | 34.88 MiB | 42.42 MiB |
| 演示动画结束后的常驻状态 | 14.49 MiB | 14.36 MiB |

动画采样峰值范围分别为 16.06–16.66 MiB、15.94–17.03 MiB，变化很小。设置打开时，新版的总占用增加约 7 MiB，原因是同时存在一个主进程和一个设置进程；不能把只看主进程的数字当作总占用。主要收益在设置关闭后：设置进程退出，整个控件、字体与工具栏缓存都随之释放。设置不会一直打开，因此选择了常驻更轻、开窗临时略重的实现。

三轮数值、采样峰值和对应可执行文件 SHA-256 见 [memory-measurements.json](memory-measurements.json)。另行采集同一个最终版主进程，设置打开时合计 **42.52 MiB**，设置子进程退出后 **11.20 MiB**，再预览实际电量并等待动画结束后 **14.56 MiB**。期间主进程没有重启。这次没有改动设置，使用 SIGTERM 结束设置子进程，验证其退出对常驻占用的影响；正常点击关闭的确认握手和自然退出由上述原生回归验证。手动关闭的补充确认未收到。这组单次过程记录不能当作三轮冷启动中位数，也不与之前已使用过的旧进程直接计算降幅。

交付时通过 LaunchServices 重新恢复新版常驻，完成实际电量预览后另一次采样约 **13.77 MiB**，ps 空闲 CPU 为 **0.0%**，只剩一个进程。该单次值会随系统内存归属和压缩状态波动，CPU 采样也不代表永远没有短暂唤醒。

| 通用包 | 原版 | 最终版 |
| --- | ---: | ---: |
| 可执行文件 | 1,359,024 B | 726,576 B |
| 应用磁盘占用（du 分配块） | 1,504 KiB | 888 KiB |
| ZIP | 460,499 B | 376,787 B |

保留 arm64、x86_64、原图案及全部功能。没有通过删图、降帧或去掉 Intel 支持来缩小体积。

## 全部模块审查

| 模块 | 审查结果及处理 |
| --- | --- |
| ChargeCore / BatterySnapshot、BatteryReader | IOPS 百分比、原始容量配对、Wh 近似值与未知数据语义保留。CF retain 与 IOObjectRelease 配对正确，未发现无界增长。保留单次完整 registry 字典读取，避免分别读取容量时破坏配对一致性。 |
| PowerEventReducer | 首次状态、阈值跨越、充满滞回及低电量模式历史均是小型固定状态，无历史列表增长。逻辑保持不变。 |
| PowerMonitor | 事件源、30 秒兜底、400 ms 去抖与唤醒监听保留；计时器和待处理工作使用弱引用，退出时移除观察者及 run-loop source。未发现循环引用。 |
| AppSettings / Preferences | 移除 ObservableObject、@Published 和 Combine；偏好 Equatable 后，值没变化就不保存或通知。应用与 UI 回调独立，关闭窗口只移除 UI 观察。子进程负责偏好持久化，主进程应用对端更新时不重复写入。沿用原 JSON 键与应用偏好域、缺失字段迁移及范围限制。 |
| 原 SettingsView | 原 NSHostingView、窗口与系统 UI 缓存关闭后长期留在常驻进程。改为原生 AppKit，当前页按需构建；只释放原生窗口仍无法释放所有系统控件缓存，因此再将设置放入按需进程。 |
| SettingsWindowController、SettingsControls、SettingsPages | 保留四页、语言、所有开关与范围、快捷键修饰符无障碍名称、登录项反馈、预览和链接。滑块刷新现有控件；换页释放旧控件与闭包。当前会话的页签、窗口位置在重开后恢复。绘图限制在各子视图 bounds，避免新系统的外扩 dirtyRect 覆盖其他控件。 |
| SettingsApplicationDelegate、SettingsProcessController、SettingsChannel、SettingsMessage | 同一个可执行文件提供 UI 角色，无第二份二进制。私有管道顺序传输消息，主线程处理模型；异步写入避免阻塞 UI。最终偏好、页签、位置须收到主进程确认，子进程发送队列排空再退出；主进程同时等退出与读端 EOF，防止快速重开请求丢失。父进程消失时子进程退出；另有 2 秒关闭兜底。数值 revision 避免旧反馈覆盖新值。 |
| ResidentInstance、main | 只有常驻角色持有进程锁，设置角色不重复监听电池或注册快捷键；O_CLOEXEC 防止子进程继承锁。snapshot/render 不启动常驻角色。重复打开应用的实际电量预览行为保留。 |
| StatusMenuController、AppDelegate | 菜单及项目建立一次，后续更新标题、百分比与剩余时间，菜单展开期间也能刷新。全局快捷键只在组合改变时重新注册，语言改变仍重新生成反馈。应用回调均用弱引用。 |
| HotKey | 独占 Carbon 注册与冲突提示保留，无辅助功能权限依赖；释放时注销快捷键和事件处理器。维持用户的 ⌘⇧E 设置。 |
| HUDController、HUDFrame、HUDView | 窗口与绘图视图按需创建，最后一段动画结束后释放。动态图仍以 60 Hz 更新；6 秒默认时间线在 2.52–5.65 秒画面静止，只设一个关闭时刻计时器，避免这段约 3.13 秒持续重绘。呈现状态与计时器类型分开，提醒仍排队、预览仍可打断。队列上限 4，结束后无隐藏窗口驻留。 |
| 显示器和位置 | 明确选择的显示器优先；设置窗口所在显示器作为“当前主显示器”的上下文传回。关闭设置清除未来的上下文，但不移动已经在播放的 HUD。原 2 pt 顶栏间距、缩放和全部几何保持。 |
| 资源、打包、依赖 | 图案资源本来已很小，保留 SVG、透明 PNG、应用图标与许可。仅对打包副本 strip -x 后重新签名；SwiftPM 产物保留诊断符号。没有第三方包，无 SwiftUI/Combine 直接源码依赖。AppKit 仍可能内部加载系统框架，不能宣称系统级零间接依赖。 |

## 验证

- 21 项核心测试通过，涵盖容量数据安全、电源事件、偏好迁移、快捷键保存、普通与减少动态效果时间线，以及静止阶段调度边界。
- 8 组原生检查通过：无变化偏好不通知、对端更新不重复持久化、锁释放、200 次连续消息、拆分消息与 EOF 前发送完成、窗口真实弱引用释放、全部四页、静止期间提醒排队、预览打断、多次 HUD 释放及实际子进程快速重开。
- 实际子进程回归记录两次自然退出，均在关闭后 1.5 秒内且 PID 消失，排除了依赖 2 秒兜底误判成功。
- 1.55 秒展开标题、3 秒数字阶段的演示 PNG 与旧版逐字节一致。通用包通过 strict codesign、Info.plist、ZIP 完整性检查；独立解压后可执行文件和所有图标资源完全一致。
- 优化前后用户偏好 JSON 比较一致。没有切换真实登录项，也没有修改系统电池、代理或节能设置。
- 用户实际点击新版设置的“预览本机电量”，确认胶囊正常弹出。之前亦已确认物理键盘 ⌘⇧E 正常触发。

## 复测与限制

```bash
bash scripts/test.sh
bash scripts/check-runtime.sh  # 需图形桌面
bash scripts/build-app.sh --universal
# 退出应用后测量，不能同时运行旧版或新版常驻实例
python3 scripts/profile-memory.py "dist/Endfield Charge.app/Contents/MacOS/EndfieldCharge" /tmp/memory.json
# 复测尚未拆分设置进程的历史版本，追加 --single-process-settings
```

采样工具编译一个临时 libproc 探针，读取 ri_phys_footprint；它要求父进程成功采样，拒绝枚举或成员读取失败，并验证设置场景的预期进程数。父子 physical footprint 的合计采用系统的逐进程归属，不等于去重后的全系统物理页面总数。0.2 秒间隔可能漏掉瞬时峰值；短测试不能证明长时间完全不增长。进程退出释放设置缓存由实际生命周期测试验证，不等于所有系统缓存均属于应用泄漏。

这些值适用于本机本次测量，其他 macOS、字体缓存、屏幕和用户行为可能不同。RSS、虚拟地址空间、磁盘包大小以及仅供开发的 .build 缓存各自独立，不能直接比较。实际多显示器、登录项审批流程、下一次真实登录、Intel/macOS 13 运行和完整物理电池周期的验证限制仍见 [verification.md](verification.md)。
